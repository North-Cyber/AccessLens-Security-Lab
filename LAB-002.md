# Lab 002 — API response privacy review

**Isolated practice branch:** `lab-002-api-privacy`  
**Status:** Intentionally insecure training exercise. The completed BOLA fix on `main` is unchanged.

## Goal

Investigate whether a browser receives more information than it needs to display a user's profile. This is a separate class of API privacy/security issue from the note-ownership bug in Finding 001.

## On Windows

In PowerShell inside your existing `accesslens-starter` folder:

```powershell
Invoke-WebRequest -Uri "https://raw.githubusercontent.com/North-Cyber/AccessLens-Security-Lab/lab-002-api-privacy/lab_002.py" -OutFile "lab_002.py"
py lab_002.py
```

In Chrome, visit `http://127.0.0.1:8001` (port 8001, not 8000).

1. Press F12 and select **Network → Fetch/XHR**.
2. Select Alex and press **Load profile**.
3. Click the request named **profile** in Network.
4. Inspect its **Response** tab. Compare every JSON field to what the webpage displays.
5. Decide which fields a real application should not send to the browser, and explain why.

**Do not make changes yet.** The next steps will be writing a failing privacy test, changing the server response to return only permitted fields, then proving the fix.

**Safety:** All data is fictional. The server binds only to `127.0.0.1`. Do not expose this practice app to the internet.
